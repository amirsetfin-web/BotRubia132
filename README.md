# بات پشتیبانی روبیکا — نسخه نهایی (با توکن رسمی BotFather)

## ⚠️ مهم‌ترین تغییر نسبت به نسخه‌های قبلی
این نسخه دیگه از `rubpy` (لاگین با QR روی یک اکانت شخصی) استفاده نمی‌کنه.
از **`rubka`** استفاده شده — کتابخانه‌ای که مستقیم با **توکن** BotFather رسمی
روبیکا کار می‌کنه، دقیقاً همون چیزی که شما دارید.

## 📁 فایل‌ها
| فایل | کار |
|---|---|
| `config.py` | توکن، رنک‌بندی Staff، وضعیت تیکت‌ها |
| `database.py` | همه‌ی کار دیتابیس (بدون تغییر نسبت به قبل، مستقل از پلتفرمه) |
| `keyboards.py` | کیبورد/دکمه‌ها با کلاس‌های `ChatKeypadBuilder` و `InlineBuilder` کتابخانه `rubka` |
| `bot.py` | منطق اصلی بات |

## 🚀 نصب و اجرا
```bash
pip install -r requirements.txt
```
سپس `config.py` رو باز کنید:
```python
BOT_TOKEN = os.environ.get("RUBIKA_BOT_TOKEN", "PASTE_YOUR_TOKEN_HERE")
INITIAL_OWNER_IDS = ["PASTE_YOUR_OWNER_SENDER_ID_HERE"]
```
- به‌جای `PASTE_YOUR_TOKEN_HERE`، توکنی که از BotFather روبیکا گرفتید رو بذارید
  (یا بهتر: بدون دست‌زدن به فایل، موقع اجرا این‌طور بنویسید تا توکن داخل کد نمونه‌ی
  گیت‌هابتون دیده نشه: `RUBIKA_BOT_TOKEN=توکن_شما python bot.py`)
- به‌جای `PASTE_YOUR_OWNER_SENDER_ID_HERE`، شناسه‌ی (sender_id) خودتون رو بذارید. برای
  پیدا کردنش، کافیه یک پیام برای بات بفرستید و همون sender_id ای که تو لاگ/دیتابیس
  ثبت می‌شه رو ببینید (یا با یک پرینت موقت تو کد چاپش کنید).

بعد:
```bash
python bot.py
```

### حالت Polling در مقابل Webhook
شما سرور/VPS ندارید، پس بات باید در حالت **Polling** اجرا بشه (خودش مرتب از
روبیکا می‌پرسه "پیام جدید داری؟") نه Webhook (که نیاز به یک آدرس عمومی HTTPS داره).
بر اساس مستندات rubka این پیش‌فرض به‌نظر می‌رسه، ولی چون قطعیتش رو نمی‌تونستم
تو این محیط تست کنم، اگه دیدید بات وصل نمی‌شه یا پیام نمی‌گیره، تو مستندات
`rubka.ir` دنبال متد `update_bot_endpoint` یا تنظیم صریح Polling بگردید.

⚠️ نکته‌ی خیلی مهم: چون هیچ سروری روشن نیست، بات فقط وقتی که خود `python bot.py`
داره اجرا می‌شه (روی پی‌سی روشن یا بعداً یک هاست/VPS) پیام دریافت می‌کنه. اگه
پی‌سی خاموش یا اسکریپت متوقف بشه، بات هم آفلاینه — همونطور که قبلاً هم گفته بودم.

### 🔐 خیلی مهم: توکن رو پابلیک نکنید
اگه `config.py` رو با توکن واقعی داخلش پوش کنید و ریپو Public باشه، هرکسی می‌تونه
توکنتون رو برداره و به‌جای شما با بات کار کنه (پیام بفرسته، تنظیماتش رو عوض کنه).
دو راه امن:
1. ریپو رو **Private** بسازید (گزینه‌ش موقع ساخت ریپو هست).
2. یا توکن رو داخل `config.py` ننویسید و همیشه با متغیر محیطی اجرا کنید
   (`RUBIKA_BOT_TOKEN=... python bot.py`)، اونوقت `config.py` که پوش می‌شه
   توکن واقعی نداره.

فایل `.gitignore` هم `*.db` (دیتابیس تیکت‌ها) رو از پوش‌شدن جلوگیری می‌کنه.

## ✅ قابلیت‌ها (خلاصه کل مسیر)
- نام ماینکرفتی قبل از منو گرفته می‌شه و همه‌جا به‌جای شناسه نشون داده می‌شه
- تیکت با شماره‌ی سراسری، جلوگیری از تیکت تکراری، گفتگوی پیوسته
- تا Claim‌نشدن تیکت، فقط یک اعلان اولیه به همه‌ی Staffها می‌ره؛ بعد از Claim فقط همون Staff پیام می‌گیره
- بستن تیکت: کاربر فقط تأیید می‌کنه، Staff باید دلیل بنویسه؛ در هر دو حالت پیام کامل (شماره، بسته‌شده توسط کی، دلیل، زمان) به همه‌ی Staffها می‌ره + آپدیت بعد از امتیاز/نظر
- رنک‌بندی: 🧰 هلپر < 🛡️ ماد < ⚙️ ادمین < 📋 منیجر < 👑 اونر
- پنل کامل Staff: فیلتر تیکت‌ها، تیکت‌های من، آمار من/سیستم، بدون‌پاسخ، معطل، جستجو، یادداشت داخلی، Claim با قفل اتمیک، انتقال، مدیریت Staff، اعلان همگانی

## ⚠️ قبل از روشن کردن واقعی حتماً این‌ها رو چک کنید
چون در این محیط نه توکن واقعی داشتم نه امکان اجرا، این‌ها رو با مستندات
`rubka.ir` / `github.com/Mahdy-Ahmadi/rubka` تطبیق بدید (تو کد هم با
`TODO/VERIFY` علامت زدم):
1. آیا `message.sender_id` و `message.chat_id` تو چت خصوصی کاربر-بات یکی هستن؟ (فرض کدم همینه)
2. حالت پیش‌فرض Polling/Webhook (بالاتر توضیح دادم)
3. اگه نوع Update خاصی برای «کاربر تازه Start زده» وجود داره، به‌جای تشخیص دستی من (چک‌کردن نبودن رکورد کاربر) از همون استفاده کنید
4. مسیر کامل «ساخت تیکت → Claim → گفتگو → بستن → امتیاز → نظر → اعلان» رو با یک اکانت واقعی تست کنید

هر باگی دیدید، دقیقاً بگید چی امتحان کردید و چه پیغامی گرفتید.
